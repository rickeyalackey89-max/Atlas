   - exactly 4 legs;

   - exact-road depletion only;
   - no player-wide depletion;
   - no road already consumed by frozen 2L or frozen 3L where the family contract forbids it.
6. Recover the existing canonical Atlas ordering/rank/control semantics from already-existing pretruth authority. **Do not invent a new control rule.**

8. Freeze/hash, per nonzero date:
   - exact candidate IDs;
   - exact road identities;
   - pregame features used by canonical Atlas ordering;
   - canonical residual Atlas ordering/ranks;
   - canonical Atlas control candidate;
   - per-date residual count.
9. Audit feature availability/missingness across the 481 rows, including whether the existing 3L pointwise feature family is present and which 4L/context-specific fields are available. This is inventory only, not a new feature-selection step.

1. Grade the already-sealed canonical Atlas control.
2. Report the current available-date control record as WIN / LOSS / NONBINARY.
3. For every date, report:
   - residual candidate count;
   - number of winning residual candidates;
   - winning-candidate prevalence;
   - canonical Atlas control result;
   - best winning candidate rank under the sealed canonical Atlas ordering;
   - whether a winner exists in top 1 / top 3 / top 5 / top 10.
4. Classify every control failure as at least:
   - `RANKING_FAILURE` if one or more legal winning residual candidates existed;

5. Keep the 15 zero-residual dates separate as `MANDATORY_ABSTENTION_NO_RESIDUAL`. They are **not losses** and must not be included in the available-date ranking denominator.

7. Do not optimize a new ranking rule against these outcomes.
